# 배틀의 전환

배틀과 도전의 탑의 장면이 어떻게 바뀌는지, 녹화한 프레임으로 본 기록입니다. 사용자(2026-11-18): "내가 말한 버벅임은 지금 측정 중인 프레임만이 아니라, 화면 전환이 급작스럽거나 일관성 없이 물 흐르듯 자연스럽지 않은 것도 뜻해." 프레임의 끊김은 `docs/BATTLE_FRAMES.md`에 적습니다. 여기는 흐름입니다.

## 1. 보는 법

- 녹화: `node scripts/record-transition.cjs`, 또는 한 흐름을 처음부터 끝까지 누르며 녹화한 스크립트(배틀 시작, 선출 셋, 선출 확정, 기술 하나). 휴대폰(390, CPU 4배 감속)과 데스크톱(1440). 빌드본.
- 접촉 시트로 250에서 500 ms마다 한 장씩 늘어놓고 본다.
- 녹화의 프레임 간격은 멈춤의 증거가 아니다: 화면이 바뀌지 않으면 합성기는 새 프레임을 보내지 않는다(선출 카드를 누른 뒤 350 ms 간격이 보였지만, 같은 순간의 CPU 프로파일에서 자바스크립트는 10 ms였다). 멈춤은 `measure-frames`로 잰다.

## 3. 전환의 문법 (3단계부터 지킬 것)

1. **무대가 화면이다.** 배틀 페이지의 장면 바뀜(로비, 선출, 열림, 판, 끝, 판 사이, 탑의 진입)은 모두 무대 위에서 일어난다. 빈 페이지, 다른 페이지, 무대 밖의 타일 뒤집기는 없다. 무대는 한 번 서면 끝까지 자리와 크기를 지킨다.
2. **준비된 것만 보인다.** 비활성 회색, 빈 세그먼트 칸, 하나씩 지어지는 목록이 한순간이라도 보이면 안 된다. 다음 장면이 준비될 때까지 지금 장면이 그대로 서 있다가, 준비되면 한 번에 바뀐다.
3. **보이는 순서는 눈이 필요로 하는 순서다.** 무대, 포켓몬, 판, 말, 키. 고를 수 없는 키는 꺼져 있고, 고를 차례가 오면 켜진다.
4. **같은 일은 같은 움직임으로.** 들어오는 것, 나가는 것, 자리를 옮기는 것의 길이와 곡선은 DESIGN.md "Battle"의 Time 한 벌이다. 탭 하나 바꾸는 데 장면 전체를 다시 연출하지 않는다(이미 본 장면은 그대로 켜진다).
5. **한 번만 알릴 말은 한 번만.** 안내는 기기에 기억되고, 무엇도 가리지 않는 자리에 선다.
